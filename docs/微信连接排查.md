# 服务器连接微信失败的排查

本次线上检查：游戏健康接口和登录校验可用，但调用微信时返回 HTTP 502、`WECHAT_UNAVAILABLE` 和“连接微信登录服务失败”。服务器诊断已确认 cURL 错误 60（缺少可信 CA），当时项目 CA 文件不可读。

## 当前修复方式：仅作用于微信登录请求

更新后的 `WechatMiniProvider.php` 在项目 `certs/cacert.pem` 存在且可读时，通过 `CURLOPT_CAINFO` 给本次微信请求指定证书。TLS 证书和域名验证继续开启；未提供项目证书时沿用 PHP 原有信任配置。

将 `wechat-project-ca-fix.zip` 解压覆盖到服务器 `D:\wwwroot\gunner-game`，保留包内目录结构。两个运行时文件应位于：

```text
D:\wwwroot\gunner-game\app\common\game\platform\WechatMiniProvider.php
D:\wwwroot\gunner-game\certs\cacert.pem
```

包内另有更新后的检查脚本和说明。该方式无需改 `php.ini`，不会改变其他项目的 CA 配置，也不需要数据库迁移。若 PHP 开启了不自动检查文件变更的 OPcache，需刷新这个站点的代码缓存；若站点共享应用程序池，先考虑回收池会影响同池站点。

如果之前仅为本次排查新增过 `curl.cainfo` / `openssl.cafile`，可将它们恢复到修改前的配置。保留其他项目原有的证书设置。

## 运行检查

将诊断包解压到服务器 PHP 项目根目录，得到 `tools/check-wechat.php` 和 `certs/cacert.pem`。不要放进 `public`。

在该目录使用**网站实际使用的那一套 PHP 和 php.ini**运行：

```bat
php tools/check-wechat.php
```

如果命令行和 IIS 使用不同安装路径，请改用网站 PHP 安装目录中的 `php.exe`；有独立配置文件时用 `-c` 指定该文件。脚本会打印 `php_binary` 和 `loaded_ini`，便于核对。

脚本不读取 `.env`，不发送 AppSecret 或玩家 code，也不访问数据库。它分别使用当前 CA 配置和项目内的 CA 证书连接微信；HTTP 200 搭配微信参数错误码是预期结果，因为本探测没有提交登录参数。修复后应看到 `game_ca_source: "project"`、`game_connectivity_ok: true`。全局 `default_ca` 仍失败不影响采用项目证书的微信请求。

## 结果判断

- `default_ca` 失败但 `bundled_ca` 返回 HTTP 200：项目证书已打通连接；更新后的游戏请求使用项目证书，无需再修改全局 CA。
- `curl_errno = 60`：证书验证失败，需检查 CA、证书链或 HTTPS 代理。
- `curl_errno = 77`：CA 文件路径或读取权限有问题。
- `curl_errno = 6`：DNS 解析失败。
- `curl_errno = 7` 或 `28`：检查服务器到 `api.weixin.qq.com:443` 的网络和防火墙。
- 两组均成功但网站接口仍失败：核对 IIS 的 PHP 程序、实际加载的 php.ini 和进程重启情况。

## 证书文件维护

确保项目内 `certs/cacert.pem` 已上传且 PHP 进程能够读取。更新证书时替换此文件即可，不需要修改共享 PHP 的信任配置。

CA 文件来源为 curl 官方分发的 Mozilla CA bundle，生成日期 2026-10-20，不包含私钥。以后可以从官方来源更新。

参考：[按请求设置 CURLOPT_CAINFO](https://curl.se/libcurl/c/CURLOPT_CAINFO.html)、[curl TLS 证书验证](https://curl.se/docs/sslcerts.html)、[CA bundle 官方来源](https://curl.se/docs/caextract.html)。
